# Backup and restore

`scripts/backup` creates consistent Klyrow PostgreSQL, Mautic MariaDB and Postal MariaDB dumps plus configuration. Plaintext staging is permitted only on tmpfs and is destroyed on exit. The script imports the approved public recipient key from `KLYROW_BACKUP_RECIPIENT_FILE`, streams the archive directly through GPG encryption, and emits only a mode-0600 `.tar.gz.gpg` file and its checksum. It fails closed when the key or tmpfs staging is unavailable. Signing keys and `.env` exist only inside the encrypted archive.

Postal DKIM private keys live in the Postal database, so the Postal database dump is required for signing identity recovery. The configuration archive covers Postal configuration/signing material and application secrets; after SMTP TLS is enabled, separately preserve the Certbot account/renewal state and Postal certificate-copy procedure. RabbitMQ is persistent runtime state but is not a substitute for source-of-truth database/configuration backups.

Validate with a disposable environment. `scripts/restore BACKUP.tar.gz.gpg` verifies the encrypted checksum, requires `CONFIRM_RESTORE=RESTORE_KLYROW`, decrypts only into tmpfs using `KLYROW_BACKUP_PRIVATE_KEY_FILE` or an approved `KLYROW_BACKUP_GNUPGHOME`, verifies the internal dump manifest, and overwrites only Klyrow databases. Configuration inside the archive is evidence/recovery material and is not automatically installed. Stop writers before production restore, take a fresh encrypted backup, restore, restart, then test login, tenant isolation, campaign state, Postal queues and a safe-mode message.

The daily timer runs at 03:40 UTC with a randomized delay. Copy encrypted archives and checksums to approved off-host storage under retention policy. A disposable restore is required after backup or schema changes; never treat archive creation alone as restore certification.
