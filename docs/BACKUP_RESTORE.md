# Backup and restore

`scripts/backup` creates consistent Klyrow PostgreSQL, Mautic MariaDB and Postal MariaDB dumps, Mautic persistent files, RabbitMQ definitions/drained-queue evidence, and configuration. Plaintext staging is permitted only on tmpfs and is destroyed on exit. The script imports the approved public recipient key from `KLYROW_BACKUP_RECIPIENT_FILE`, streams the archive directly through GPG encryption, and emits only a mode-0600 `.tar.gz.gpg` file and its checksum. It fails closed when the key or tmpfs staging is unavailable, when RabbitMQ is not drained, or when the encrypted copy cannot be checksummed on the separately mounted `KLYROW_BACKUP_OFFHOST_DIR`. Signing keys and `.env` exist only inside the encrypted archive.

Postal DKIM private keys live in the Postal database, so the Postal database dump is required for signing identity recovery. The configuration archive covers Postal configuration/signing material and application secrets; after SMTP TLS is enabled, separately preserve the Certbot account/renewal state and Postal certificate-copy procedure. RabbitMQ is persistent runtime state but is not a substitute for source-of-truth database/configuration backups.

Validate with a disposable environment. `scripts/restore-verify BACKUP.tar.gz.gpg` requires exact image digests, restores into uniquely named tmpfs containers with no network, validates the database/migration authorities, imports RabbitMQ definitions, and starts the exact Klyrow gateway with every external-delivery gate false. It never attaches to the production Compose project. `scripts/restore BACKUP.tar.gz.gpg` is the separate destructive disaster-recovery command: it verifies the encrypted checksum, requires `CONFIRM_RESTORE=RESTORE_KLYROW`, decrypts only into tmpfs using `KLYROW_BACKUP_PRIVATE_KEY_FILE` or an approved `KLYROW_BACKUP_GNUPGHOME`, verifies the internal dump manifest, and overwrites only Klyrow databases. Configuration inside the archive is evidence/recovery material and is not automatically installed. Stop writers before production restore, take a fresh encrypted backup, restore, restart, then test login, tenant isolation, campaign state, Postal queues and a safe-mode message.

The daily timer runs at 03:40 UTC with a randomized delay. `scripts/archive-offhost` accepts ciphertext only, requires a mounted off-host filesystem in production, uses an atomic copy, verifies the copied digest, and writes a sanitized receipt. A disposable restore is required after backup or schema changes; never treat archive creation alone as restore certification.
